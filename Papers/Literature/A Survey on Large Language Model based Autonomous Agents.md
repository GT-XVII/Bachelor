## Abstract

Autonomous agents have long been a research focus in academic and industry communities. Previous research often focuses on training agents with limited knowledge within isolated environments, which diverges significantly from human learning processes. Recently, through the acquisition of vast amounts of web knowledge, large language models (LLMs) have shown potential in human-level intelligence, leading to a surge in research on LLM-based autonomous agents.

This paper presents a comprehensive survey of these studies, delivering a systematic review of LLM-based autonomous agents from a holistic perspective. The survey first discusses the construction of LLM-based autonomous agents, proposing a unified framework that encompasses much of previous work. Then, it presents an overview of the diverse applications of LLM-based autonomous agents in social science, natural science, and engineering. Finally, it delves into the evaluation strategies commonly used for LLM-based autonomous agents. Based on the previous studies, the paper also presents several challenges and future directions in this field.

**Keywords:** Autonomous agent, Large language model, Human-level intelligence

## 1. Introduction

The introduction establishes that autonomous agents have historically been trained with limited knowledge in isolated environments. This contrasts with human learning, which draws from diverse knowledge sources. LLMs, having absorbed vast web knowledge, demonstrate potential for human-level intelligence and serve as central controllers in agent construction.

**Advantages of LLM-based Agents over Traditional Approaches:**
- Comprehensive internal world knowledge enabling informed actions without domain-specific training
- Natural language interfaces for enhanced human interaction and explainability
- Potential to replicate human-level decision-making in open-domain settings

## 2. LLM-based Autonomous Agent Construction

Agent construction involves two critical aspects:
1. **Architecture Design** — Creating rational agent architectures to maximise LLM capabilities
2. **Capability Acquisition** — Enabling agents to acquire task-specific skills and knowledge

> "Architecture design is analogous to defining the network structure, while capability acquisition resembles the process of learning network parameters"

---

## 2.1 Agent Architecture Design

The paper proposes a **unified agent framework** comprising four core modules:

- **Profiling Module** → influences memory and planning
- **Memory Module** → informs planning and action
- **Planning Module** → guides action execution
- **Action Module** → downstream environment interface

---

### 2.1.1 Profiling Module

**Purpose:** Identify and define the agent's role, influencing behaviour through prompt-based profile specification.

**Profile Components:**
- Basic information (age, gender, career)
- Psychology information (personality traits)
- Social information (relationships with other agents)

**Three Profile Creation Strategies:**

**1. Handcrafting Method**
Manually specified profiles using natural language descriptions. Examples include Generative Agent, MetaGPT, and ChatDev.
- Advantages: Flexible profile assignment
- Disadvantages: Labour-intensive for large-scale deployments

**2. LLM-Generation Method**
Profiles automatically generated by LLMs based on specified rules and seed examples.
- Advantages: Reduces time and effort for large populations
- Disadvantages: May lack precise control; potential inconsistencies

**3. Dataset Alignment Method**
Profiles derived from real-world datasets converted into natural language.
- Advantages: Accurately captures real population attributes
- Disadvantages: Limited to existing data

---

### 2.1.2 Memory Module

**Critical Role:** Stores environmental information and leverages recorded memories to facilitate future actions, enabling agents to accumulate experiences and behave consistently.

#### Memory Structures

**Unified Memory:**
- Simulates human short-term memory only
- Implemented through in-context learning via prompts
- Examples: RLP, SayPlan, CALYPSO, DEPS
- Advantages: Straightforward implementation
- Disadvantages: Limited context window restricts comprehensive memory incorporation

**Hybrid Memory:**
- Explicitly models both short-term and long-term memory
- Short-term memory: temporary buffer for recent perceptions
- Long-term memory: consolidates important information via vector databases
- Examples: Generative Agent, AgentSims, GITM, Reflexion, SCM, SimplyRetrieve, MemorySandbox
- Advantages: Enhanced long-range reasoning and experience accumulation
- Disadvantages: Increased complexity in design and retrieval

#### Memory Formats

| Format | Characteristics | Examples |
|---|---|---|
| Natural Language | Flexible, rich semantic information | Reflexion, Voyager |
| Embeddings | Enhanced retrieval efficiency | MemoryBank (dual-tower dense retrieval) |
| Databases | Efficient manipulation, comprehensive management | ChatDB (SQL operations) |
| Structured Lists | Concise semantic conveyance | GITM (hierarchical tree), RET-LLM (triplets) |

#### Memory Operations

**Memory Reading:**
Extraction of meaningful information from memory to enhance agent actions.

```
m* = arg max_{m ∈ M} (α·s_rec(q,m) + β·s_rel(q,m) + γ·s_imp(m))
```

Where:
- q = query (task or context)
- M = set of all memories
- s_rec = recency scoring function
- s_rel = relevance scoring function
- s_imp = importance scoring function
- α, β, γ = balancing parameters

Key extraction criteria: **Recency**, **Relevance**, and **Importance**

**Memory Writing:**
Storage of environmental information in memory. Key challenges:
1. Memory Duplication — handling similar information
2. Memory Overflow — managing storage limits

**Memory Reflection:**
Enables agents to summarise and infer abstract, high-level information from experiences.
- Generative Agent: Generates insights from past memories and questions
- GITM: Summarises successful action sequences into common patterns
- ExpeL: Compares successful/failed trajectories for learning

---

### 2.1.3 Planning Module

**Purpose:** Empower agents with capability to deconstruct complex tasks into simpler subtasks, enabling more reasonable and reliable behaviour.

#### Planning Without Feedback

**Single-path Reasoning:**
Final task decomposed into intermediate steps connected sequentially.
- Chain of Thought (CoT): Inputs reasoning steps as prompt examples
- Zero-shot-CoT: Generates reasoning via trigger phrases ("think step by step")
- Re-Prompting: Validates prerequisites before plan generation
- ReWOO: Separates plans from external observations
- HuggingGPT: Decomposes tasks and solves each via Hugging Face models

**Multi-path Reasoning:**
Reasoning organised into tree-like structures where intermediate steps have multiple possible successors.
- Self-consistent CoT (CoT-SC): Generates multiple reasoning paths, selects highest-frequency answer
- Tree of Thoughts (ToT): Tree-like structure with LLM-evaluated nodes, BFS/DFS search
- Graph of Thoughts (GoT): Expands tree structures to graphs
- RAP: Builds world models using Monte Carlo Tree Search (MCTS)

**External Planner:**
Leverages well-developed external planning tools for domain-specific problems.
- LLM+P: Transforms tasks into Planning Domain Definition Language (PDDL)

#### Planning With Feedback

**Environmental Feedback:**
Obtained from objective environments or virtual systems.
- **ReAct:** Uses thought-act-observation triplets; observations influence future thoughts
- Voyager: Incorporates execution progress, errors, and verification results
- DEPS: Provides detailed failure reasons for effective plan revision
- LLM-Planner: Dynamically updates plans when encountering mismatches

**Human Feedback:**
Subjective signals that align agents with human values and alleviate hallucination.

**Model Feedback:**
Internal feedback generated by pre-trained models.
- Self-refine: Output-feedback-refinement iterative cycles
- Reflexion: Generates detailed verbal feedback for iterative improvement

---

### 2.1.4 Action Module

**Responsibility:** Translate agent decisions into specific outcomes; downstream interface with environment.

**Influenced by:** Profile, memory, and planning modules

#### Action Goal

- **Task Completion:** Actions aimed at accomplishing specific objectives
- **Communication:** Actions taken to share information or collaborate with other agents or humans
- **Environment Exploration:** Agents balance exploration-exploitation trade-offs to expand perception

#### Action Production

- **Via Memory Recollection:** Actions generated by extracting memory information according to current task
- **Via Plan Following:** Actions follow pre-generated plans

#### Action Space

**External Tools — APIs:**
- HuggingGPT, WebGPT, TPTU, Gorilla, ToolFormer, API-Bank, ToolLLaMA, RestGPT, TaskMatrix.AI

**External Tools — Databases & Knowledge Bases:**
- ChatDB (SQL), MRKL (knowledge bases and expert systems), OpenAGI

**External Tools — External Models:**
- ViperGPT, ChemCrow, MM-REACT

**Internal Knowledge:**
- Planning capability (task decomposition)
- Conversation capability (dialogue generation)
- Common sense understanding

#### Action Impact

- **Changing Environments:** Direct alteration of environment states
- **Altering Internal States:** Changes to agent itself including memory updates, new plans
- **Triggering New Actions:** Sequential action generation where one action initiates subsequent actions

## 2.2 Agent Capability Acquisition

### With Fine-tuning
- Fine-tuning with Human Annotated Datasets (CoH, WebShop, EduChat)
- Fine-tuning with LLM Generated Datasets (ToolBench, Socially Alignment)
- Fine-tuning with Real-world Datasets (MIND2WEB, SQL-PaLM)

### Without Fine-tuning

**1. Prompt Engineering:**
Natural language descriptions enhance LLM capabilities without parameter adjustment.
- CoT, CoT-SC, ToT, RLP, Retroformer

**2. Mechanism Engineering:**

*Trial-and-error:* Agent performs action → pre-defined critic judges → incorporates feedback if unsatisfactory

*Crowd-sourcing:* Multiple agents provide responses; consensus-building through iterative discussion

*Experience Accumulation:* Agents store successful actions in memory for similar future tasks (GITM, Voyager, AppAgent, MemPrompt)

*Self-driven Evolution:* Agents autonomously improve through self-directed learning and feedback

> "In the era of LLMs, the model capability can be acquired either by training/fine-tuning the model parameters or designing delicate prompts"

## Thesis Analysis Notes

## Wang, L., et al. (2023). A Survey on Large Language Model based Autonomous Agents

**Citation key:** wang2023survey
**Thesis relevance:** Ch 2.3 (defining agent-based systems), Ch 3.3 (agent architecture design)

### Core Argument

Wang et al. argue that LLMs represent a qualitative shift in autonomous agent construction because they supply the internal world knowledge and language reasoning capacity that prior agent architectures had to encode externally or acquire through narrow domain training. The paper proposes a unified four-component framework — profiling, memory, planning, action — that subsumes the design decisions of most prior systems and can serve as a principled blueprint for new agent architectures. The survey further claims that the central challenge has moved from capability acquisition (training agents to know things) to capability orchestration (designing the right mechanisms to deploy what LLMs already know).

### The Four-Component Framework (Critical for Ch 2.3)

**Profiling Module:** Defines the agent's identity and behavioural disposition through prompt-based specification. This includes basic attributes (role, domain), psychological traits (personality), and relational attributes (position in a multi-agent system). The profile shapes how the agent interprets queries and prioritises actions — in a retrieval context, this translates directly to the system prompt that defines which sources to trust and how to frame answers.

**Memory Module:** Stores perceived environmental information and past experience, enabling consistent behaviour across multi-step tasks. The survey distinguishes between unified memory (short-term only, held in-context) and hybrid memory (short-term buffer plus long-term vector store). Memory retrieval is formalised as maximising a weighted sum of recency, relevance, and importance scores: `m* = argmax_{m∈M}(α·s_rec + β·s_rel + γ·s_imp)`. Memory formats include natural language, embeddings, structured databases, and lists — often combined within a single system.

**Planning Module:** Decomposes complex tasks into manageable subtasks. The survey distinguishes planning without feedback (single-path CoT, multi-path ToT/GoT, external PDDL planners) from planning with feedback (environmental signals, human corrections, model self-critique). The ReAct framework is positioned as the canonical feedback-driven planning approach: a loop of thought → action → observation that allows the agent to revise its plan in light of tool results.

**Action Module:** Translates plans into executable operations. The action space encompasses external tools (APIs, databases, specialist models), internal knowledge (planning and conversational capability), and their outputs can change environment state, update the agent's own memory, or trigger further actions. This is the component that directly maps onto tool-calling behaviour in a retrieval agent.

### Planning and Tool Use (Critical for Ch 3.3)

The survey characterises planning under uncertainty primarily through the feedback-driven planning paradigm. ReAct (Yao et al., 2023) is the central reference: by interleaving reasoning traces with tool invocations and folding observations back into the next reasoning step, the agent can recover from retrieval failures and iteratively refine its answer. This contrasts with single-pass RAG, where the retrieval decision is made once and cannot be revised based on what was returned.

Tool invocation is framed as an action-space problem: the agent selects from a defined set of tools (APIs, databases, external models), and the choice is driven by the current planning state and memory context. The survey catalogues a wide range of tool categories — web search APIs, SQL databases, domain-specific models — which maps cleanly onto a multi-source retrieval agent that has separate tools for GitHub Issues, documentation corpora, and PDF whitepapers. The key design insight from the survey is that tool interfaces should return structured observations that the planning module can reason over, not raw data.

For complex, multi-hop queries the survey advocates multi-path reasoning (ToT, GoT) combined with feedback loops. For simpler single-source queries, a single-path ReAct loop with environmental feedback is sufficient. This suggests a tiered tool-selection strategy for the thesis agent: classify query complexity first, then route to either a direct retrieval tool call or a multi-step decomposition.

### Evaluation Dimensions in the Survey

The survey identifies two high-level evaluation strategies — subjective (human judgment) and objective (quantitative metrics) — but does not define standardised metrics as precisely as RAGAS does for RAG systems. For agent-specific evaluation the survey implicitly surfaces several relevant dimensions:

- **Task completion rate:** Whether the agent successfully resolved the query (directly relevant to answer relevance in this thesis's evaluation)
- **Efficiency:** Computational resource use and response time (maps to latency and token cost metrics)
- **Robustness:** Maintaining performance across prompt variations and noisy inputs (maps to the thesis's noise robustness and negative rejection dimensions from Gao et al.)
- **Role consistency:** Whether the agent's behaviour matches its defined profile across sessions (relevant to reproducibility of evaluation runs)
- **Hallucination rate:** Not formalised in the survey but noted as a key challenge (maps to faithfulness in RAGAS)

The survey does not address retrieval-specific metrics (context relevance, source routing accuracy) — these are gaps the thesis fills by layering RAGAS and custom tool-call logging on top of the agent framework.

### Critical Notes

**What the survey covers well:**
- The four-component framework is the most useful contribution for Chapter 2.3 — it gives this thesis a principled vocabulary (profiling, memory, planning, action) for describing the agent architecture in Chapter 3.3.
- The taxonomy of planning strategies (single-path vs multi-path, with vs without feedback) is directly applicable when justifying the choice of a ReAct-style loop over a one-shot decomposition approach.
- The tool-use catalogue under the Action Module validates the thesis's design decision to give the agent separate, typed tools per source.

**Gaps the thesis must address:**
- The survey does not evaluate retrieval quality in the information retrieval sense. It discusses agent performance on task benchmarks (Minecraft, software development, social simulation) rather than QA retrieval benchmarks. The thesis must therefore draw retrieval evaluation methodology from RAGAS and Gao et al. rather than from Wang et al.
- There is no cost or latency analysis in the survey. The thesis's token-cost and latency metrics are original contributions not covered here.
- The survey predates the specific agentic RAG literature (Ferrazzi et al. 2026, AgenticRAG 2025) that directly benchmarks agent systems on retrieval tasks. Wang et al. should be cited for the foundational framework; those later papers should be cited for empirical retrieval comparisons.
- The survey covers multi-agent systems extensively (social simulation, collaborative coding) but the thesis uses a single-agent architecture. This should be noted as a deliberate scope decision in Chapter 3.3 to avoid reviewer confusion.
- Evaluation methodology in the survey is underdeveloped relative to RAG evaluation literature. The thesis's use of RAGAS, BERTScore, and LLM-as-judge fills this gap and should be positioned as going beyond what the agent survey tradition has formalised.
